# WEB програмування — лабораторні 1–9

Селіванов Назар, БЗІП-23. Варіант 5 там, де методичка містить варіанти.
Робота №2 виконує загальні приклади; №7–9 виконують загальні завдання, а не лише пункт 5.

## Швидкий запуск на Windows

Потрібні Node.js 22+ і PHP 8.3+ з `pdo_sqlite`, `openssl`. База SQLite створюється автоматично; MySQL не потрібен.

1. Розпакуйте архів. Відкрийте папку `WEB_Labs_variant_5` у VS Code.
2. У терміналі цієї папки виконайте `npm.cmd ci`, потім `npm.cmd run build`.
   В архіві вже є готова папка `dist`, тому для першого перегляду ці команди можна пропустити.
3. Запустіть `./scripts/start-local.ps1` у PowerShell. Якщо PHP не у PATH,
   задайте шлях: `./scripts/start-local.ps1 -PhpPath 'C:\шлях\до\php.exe'`.
   Для портативного PHP додайте `-ExtensionDir 'C:\шлях\до\ext'`.
4. Відкрийте **http://127.0.0.1:8087/**. Для №6 і №9 спочатку зареєструйте власний навчальний обліковий запис на сторінці №7, потім увійдіть.
5. Зупинка тільки процесів цього комплекту: `./scripts/stop-local.ps1`.

Порти: сайт 8087, датчики 8091, постачальник 8092. Якщо порт зайнятий, запуск не змінює наявні процеси.
Паролі створює користувач; жодних робочих паролів, ключів або баз із персональними даними в архіві немає.
База, сесії, локальний ключ шифрування й резервні копії зберігаються в `data` і не потрапляють до GitHub.

## Перевірки

`npm test` — JavaScript та PHP HTTP інтеграційні тести з окремою тимчасовою базою, яка видаляється після завершення.
`PHP_BIN` задає нестандартний шлях до PHP. `PHP_ARGS` — додаткові аргументи, розділені `|`.
`npm run build` — збірка React. `npm run monitor` — перевірка сайту на 8087.
`php scripts/backup.php` — перевірена копія SQLite та локального ключа, якщо ключ зберігається у файлі.
`scripts/backup-loop.mjs` запускає копіювання автоматично кожні 60 секунд; Docker-служба — кожну годину.
Копії містять конфіденційні дані і ключ: не публікуйте `data/backups`.
Відновлення: зупиніть сервери, збережіть поточну базу окремо, скопіюйте обрану `.sqlite` як `data/labs.sqlite` і відповідний `.sqlite.key` як `data/key.bin`; для ключа із середовища потрібно зберегти `LAB_ENCRYPTION_KEY` окремо. Не змішуйте базу та ключ від різних копій.

## Локальне HTTPS

`python scripts/make-local-cert.py` створює самопідписаний сертифікат на 30 днів; потрібен пакет cryptography.
В іншому терміналі запустіть PHP на 8090 з `LAB_HTTPS=1` і тим самим `LAB_DATA_DIR`, потім `node scripts/https-proxy.mjs`.
Адреса — `https://localhost:8443/`. Сертифікат не додається до довірених сертифікатів Windows.
Автоматична TLS-перевірка використовує саме створений сертифікат як CA, не вимикає перевірку TLS.
Для публічного сайту потрібен сертифікат від довіреного центру, а не обхід попередження браузера.

## Docker і CI

За наявності Docker: `docker compose up --build -d --wait`; потім відкрийте адресу на 8087.
`docker compose down` зупиняє контейнерний комплект, зберігаючи том із даними. Не використовуйте `down -v`, якщо база потрібна.
Контейнер `backup` перевіряє цілісність і свіжість останньої копії SQLite та відповідність локального ключа, а не HTTP вебсервера. Копія старша за 65 хвилин означає `unhealthy`; помилка копіювання перезапускає службу.
Workflow `ci.yml` після push перевіряє PHP, запускає тести, збирає React, перевіряє залежності, збирає Docker і запускає тимчасовий стек на GitHub runner.
Тимчасовий стек CI не є публічним хмарним сайтом.

## Хмарне розгортання

Workflow `deploy.yml` готовий для **вже наявного** Linux-сервера, наприклад AWS EC2.
Він не створює акаунтів або платних ресурсів і запускається лише вручну.
Потрібні Docker Compose на сервері, довірений сертифікат `web-labs/certs/cert.pem` і `key.pem`, GitHub environment `production` та секрети `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`.
Ключ хоста треба перевірити окремим довіреним каналом; перевірка SSH не вимикається.
Після розгортання перевірте HTTPS health endpoint, Secure cookie, матеріали, CRUD, резервні копії та журнали.
Том забезпечує збереження даних між перезапусками на одному сервері, але не замінює віддалене резервування.
Публічне розгортання й віддалені запуски CI у звіті позначаються завершеними тільки після фактичного виконання.
